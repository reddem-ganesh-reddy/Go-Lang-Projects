Let's test Employee Pagination, Filtering and Sorting in GraphiQL.

Your Employee GraphQL fields use `snake_case`, so use the following queries.

GraphQL URL: `http://localhost:8082/graphql`

## 1. Pagination

Test 1: Default pagination

```
query {
  employees {
    employees {
      id
      name
      email
      department_id
    }
    pagination {
      total_records
      current_page
      page_size
      total_pages
    }
  }
}
```

Test 2: Page 1, 2 employees

```
query {
  employees(query: {
    page: 1
    limit: 2
  }) {
    employees {
      id
      name
      email
    }
    pagination {
      total_records
      current_page
      page_size
      total_pages
    }
  }
}
```

Test 3: Page 2, 2 employees

```
query {

      id
```

## 4. Combine all parameters

You can combine pagination, filtering and sorting in one query.

Test 10: Name + pagination + sorting

```

  employees(query: {
    name: "a"
    page: 1
    limit: 3
    sort_by: "name"
    sort_order: "asc"
  }) {
    employees {
      id
      name
      email
    }
    pagination {
      total_records
      current_page
      page_size
      total_pages
    }
  }
}
```

## 5. Sorting options to test

| Sort field   | Ascending | Descending |
| ------------ | --------- | ---------- |
| ID           | `asc`     | `desc`     |
| Name         | `asc`     | `desc`     |
| Email        | `asc`     | `desc`     |
| Created date | `asc`     | `desc`     |

## 6. Important combination tests

Try these combinations too:

- Name + Email
- Name + Department ID
- Email + Department ID
- Name + Email + Department ID
- Pagination + Sorting
- Filtering + Sorting
- Filtering + Pagination + Sorting

Expected behaviour: All parameters are optional. If omitted, your service should use page `1`, limit `10`, sort by `id`, and sort order `asc`. The filters should work together using AND conditions.

Run these queries in order. If any query returns a GraphQL error, share the exact error before changing the Go code.
